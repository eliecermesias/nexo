# Requerimientos de Nexo

## Alcance Funcional

### User Management

Los usuarios deben gestionar información personal, profesional, fiscal, comercial, bancaria, documental, plantillas, consecutivos y preferencias de seguridad.

### Client Companies

Cada `ClientCompany` debe almacenar identificación fiscal, información de contacto, información de facturación, condiciones de pago, configuración de cumplimiento, documentos requeridos, reglas de entrega, reglas de paquete PDF y estado activo.

### Services Catalog

Los usuarios deben administrar registros `Service` con nombre, descripción, categoría, tipo de precio, precio base, moneda, reglas de impuestos y estado activo.

### Service Valuation

`ServiceValuationService` debe calcular subtotales, impuestos, descuentos, retenciones, totales, valores pagados y saldos pendientes para cotizaciones, propuestas, facturas, cuentas de cobro y cargos finales.

### Quotes

`Quote` debe incluir empresa cliente, número de cotización, items de servicio, precios, descuentos, impuestos, retenciones, subtotal, total, moneda, fecha de validez, estado, versión de plantilla, términos y notas.

### Proposals

`Proposal` debe incluir alcance, objetivos, servicios, entregables, cronograma, condiciones comerciales, valores financieros, moneda, plantilla, versión y estado.

### Invoices

El sistema debe soportar documentos internos de soporte y facturas legales externas. Los números externos de factura deben ser únicos por usuario y empresa cliente.

### Payment Claims

`PaymentClaim` debe incluir empresa cliente, número de documento, servicios cobrados, valor total, moneda, cuenta bancaria, método de pago, documentos requeridos, resultado de cumplimiento, paquete PDF, estado, fecha de emisión, fecha de vencimiento y notas.

### Compliance Matrix

Cada `ClientCompany` puede tener una `ComplianceMatrix` que define documentos requeridos para una `PaymentClaim`.

Campos del requisito:

- Document type.
- Requirement name.
- Mandatory or optional.
- Requires expiration date.
- Requires approval.
- Requires file upload.
- Can be generated by system.
- Must be attached separately.
- Must be merged into final PDF.
- Merge order.
- Renewal frequency.
- Blocking rule.
- Validation rule.
- Active status.

### Compliance Validation Engine

`ComplianceValidationService` debe entregar estado global, documentos válidos, faltantes, vencidos, rechazados, pendientes de aprobación, razones de bloqueo y acciones sugeridas.

### PDF Packages

El sistema debe generar PDFs desde plantillas, combinar documentos cargados y generados, conservar el orden, agregar portada o tabla de contenido cuando aplique, almacenar archivos de forma segura y mantener historial de generación.

## Reglas de Negocio

1. Un usuario no puede acceder a datos de otro usuario.
2. Cada documento de negocio pertenece a un alcance propietario autenticado.
3. Una `PaymentClaim` no puede radicarse si faltan requisitos obligatorios bloqueantes.
4. Los documentos cargados deben vincularse al usuario, empresa cliente, requisito documental y documento de negocio.
5. Los documentos requeridos vencidos invalidan el cumplimiento salvo que el requisito sea opcional o no bloqueante.
6. Los números externos de factura no se pueden duplicar para el mismo usuario y empresa cliente.
7. Los paquetes PDF generados deben conservar versión, hash, usuario generador y fecha de generación.
8. Los consecutivos internos deben evitar duplicados y mantener historial.
9. Las reglas documentales por cliente deben ser configurables, no quemadas en código.
10. Las descargas de archivos requieren autorización.
